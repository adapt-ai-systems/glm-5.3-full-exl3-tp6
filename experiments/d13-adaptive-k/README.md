# D13: adaptive, phase-aware MTP draft length (TP6, not shipped)

Each decode step, `adaptive_k_phase.py` (a vLLM scheduler class) picks k, the number of MTP drafts, to maximise
expected tokens per ms: expected tokens from a running estimate of per-position acceptance, step cost from a
measured table (`costtable.py`; ~+7.9 ms per extra draft on TP6). In `phase` mode it keeps separate acceptance
state for reasoning, content, code fences and tool calls, and switches k at phase boundaries. It is a port of
Matt Mastracci's adaptive-k scheduler (DFlash2 drafts, Apache-2.0) to the sequential MTP drafter; see
THIRD_PARTY_NOTICES.md.

`overlay/` = three vLLM files regenerated by `make_overlays.py` from the base image's copies: they add FULL
decode CUDA graphs for every query length k+1 (`GLM_D13_QLENS=2,3,4,5`) and stop capture sizes being rounded to
multiples of k+1 (`GLM_D13_NO_CG_ROUND=1`); unset env = stock behaviour.

## Boot (on top of launch/tp6/launch.sh, MTP k=4)

Bind `adaptive_k_phase.py` to `vllm/v1/core/sched/adaptive_k_phase.py` and the three overlays to
`vllm/config/compilation.py`, `vllm/v1/cudagraph_dispatcher.py`, `vllm/v1/worker/gpu_model_runner.py`; add
`--scheduler-cls vllm.v1.core.sched.adaptive_k_phase.AdaptiveKScheduler`, capture sizes
`[2,3,4,5,6,8,9,10,12,15,16,20]`, and env `GLM_D13_QLENS=2,3,4,5 GLM_D13_NO_CG_ROUND=1
VLLM_ADAPTIVE_K_MODE=phase VLLM_ADAPTIVE_K_COST_MS=2:55,3:62,4:70,5:77` (verified tokens:ms). Optional
`VLLM_ADAPTIVE_K_CONTROL=<file>`: a line `force N` | `adapt` | `phase`, plus an optional `cost ...` line, read live.

## Measured (one D13 boot switched between modes, plus the stock boot; TP6, fabric at MTU 9000)

| workload | fixed k=4 (stock) | k=4 via D13 `force 4` | D13 `adapt` | D13 `phase` |
|---|---|---|---|---|
| pbench prose decode (3 reps, T=0.7) | 27.85 | 26.87 | 30.88 | 31.17 |
| 40 real single-turn prompts (T=0.7, 700 tok; not published) | 34.06 | 34.61 | 36.03 | 36.33 |
| 16 tool-call / JSON prompts (T=0) | 44.60 | 49.86 | 47.38 | 47.10 |

The tool/JSON row is inconclusive: the two k=4 columns differ by 12%. In `phase` mode tool calls ran at k=4
100% of the time. All 12 tool prompts produced parseable tool calls in every mode. Not run: the A/B on a longer
tool/JSON/code bench, a 50-minute mixed soak, and KV sizing on this boot.
